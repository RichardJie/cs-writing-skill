# 中英混排与计算机技术写作去 AI 味指南（Bilingual CS & Tech Writing Guide）

专为计算机科学（CS）、人工智能（AI/ML）、系统工程与开源开发者文档打造的**中英双语混排去翻译腔与排版规范指南**。

> **模块协同导航（[../SKILL.md](../SKILL.md)）：** 处理中英混排技术文稿时，请将本规范与母语深度指南 [../chinese.md](../chinese.md)（七步手术法与余光中去西化十二病灶）叠加使用；涉及学术论文/审稿回复时先读 [../paper-boundaries.md](../paper-boundaries.md) 与 [academic-prose-and-rebuttal.md](academic-prose-and-rebuttal.md)；涉及 README/复盘报告/PRD 体裁规范参见 [genres-playbook.md](genres-playbook.md)。

当大模型用中文撰写计算机技术内容时，由于底层预训练语料由英文代码、英文论文与英文文档绝对主导，模型实质上在后台执行着**“隐式英译中（Implicit English-to-Chinese Calquing）”**。这会导致三大典型顽疾：
1. **排版粘连与符号错乱**：汉字、英文标识符、数字、反引号与全半角标点混作一团；
2. **术语精神分裂**：一边把不该翻的专有概念硬译成滑稽的“香草模型/地面真相”，一边又把早有地道中文的基础词写成“这个 function 抛了 exception”的散装夹杂体，且同篇术语前后摇摆；
3. **英文语法嵌套中文（English-Syntax-in-Chinese）**：用汉字填满英语的抽象语法树（AST）——满纸`一个/一种`、无生命主语拟人施事、右分支定语硬塞成连环`的`字长龙、生硬的`被`字句与`通过……的方式实现……`。

本指南融合 Sparanoid《中文文案排版指北》（盘古之白）、阮一峰《中文技术文档的写作规范》、Microsoft / Google / Apple 简体中文技术本地化风格指南，以及一线 CS 学术与工程写作实践，建立一套可直接落地的技术中文标准。

## 一、 盘古之白与中英混排精密排版规范（Pangu Spacing & Typography）

干净克制的中西文留白是技术文章专业度的第一道门面，既要消除“中英粘连”的压迫感，又要严防机械脚本乱加空格造成的排版破碎。

### 1.1 三条黄金留白律（必加 1 个半角空格）

1. **汉字与英文单词/缩写之间加半角空格**：
   * ❌ `在GitHub上开源了基于PyTorch的推理引擎。`
   * ✅ `在 GitHub 上开源了基于 PyTorch 的推理引擎。`
2. **汉字与阿拉伯数字之间加半角空格**：
   * ❌ `集群共部署了16个节点，单卡吞吐量提升3倍。`
   * ✅ `集群共部署了 16 个节点，单卡吞吐量提升 3 倍。`
3. **数字与物理/存储/时间/频率单位之间加半角空格**（遵循国际单位制 SI 惯例）：
   * ❌ `显存占用24GB，主频3.6GHz，尾延迟控制在50ms以内，带宽达100Gbps。`
   * ✅ `显存占用 24 GB，主频 3.6 GHz，尾延迟控制在 50 ms 以内，带宽达 100 Gbps。`

### 1.2 八大严禁乱加空格的精确例外（Exceptions）

| 例外场景 | ❌ 错误示范 | ✅ 正确规范 | 原理解析 |
|:---|:---|:---|:---|
| **1. 百分号 `%` 与角度 `°`** | `提升了 18.5 %`、`旋转 90 °` | `提升了 18.5%`、`旋转 90°` | `%` 与 `°` 紧贴数字；温度推荐写 `65 °C` 或全文统一 `65°C`，但数字与 `%` 永不空格 |
| **2. 全角中文标点两侧** | `支持 Python ，Rust 和 Go 。` | `支持 Python、Rust 和 Go。` | 全角标点（`，。；：？！、“”《》`）自身已含半格留白，再加空格会显得松垮断裂 |
| **3. 斜杠 `/` 并列或路径** | `I / O 多路复用`、`TCP / IP` | `I/O 多路复用`、`TCP/IP`、`读/写锁` | 斜杠两侧紧贴，不加空格 |
| **4. 倍数后缀 `x` 与版本号 `v`** | `实现了 3.2 x 加速`、`v 2.1.0` | `实现了 3.2x 加速`（或 `3.2 倍`）、`v2.1.0` | 紧凑前缀/后缀修饰符与数字绑定 |
| **5. 货币符号前缀** | `耗资 $ 200 万` | `耗资 $200 万`（或 `200 万美元`） | 货币符号紧贴数字；正式技术文本更推荐直接写中文单位`万美元 / 元` |
| **6. 品牌与专有连写原貌** | `豆瓣 FM`、`i Phone` | `豆瓣FM`、`iPhone`、`macOS` | 严格遵从官方注册形态 |
| **7. 全角括号贴汉字** | `注意力机制 （Attention）` | `注意力机制（Attention）` | 中文正文统一使用全角括号 `（）` 时，括号外侧紧贴汉字不加空格，括号内侧紧贴英文不加空格 |
| **8. 行内数学公式定界符内** | `$ x_i + y_i $` | `计算 $x_i + y_i$ 的梯度。` | `$` 外侧与汉字之间留半角空格（紧邻全角标点除外），`$` 内侧紧贴数学符号 |

### 1.3 专有名词大小写零容忍铁律（Official Casing）

AI 与粗心作者常在句首或小标题里篡改开源项目与技术品牌的官方大小写。**技术专有名词大小写神圣不可侵犯**，即使位于句首，也要保持原貌（或调整语序避开句首）：

* **基础设施与语言**：`GitHub`（禁 `Github` / `github`）、`GitLab`、`JavaScript`（禁 `Javascript`）、`TypeScript`、`Node.js`、`Go` / `Golang`、`C++`、`macOS`（禁 `MacOS`）、`iOS`、`Linux`、`Kubernetes`（或 `K8s`）、`PostgreSQL`、`MySQL`、`ClickHouse`、`gRPC`、`GraphQL`、`WebAssembly`、`NVMe`、`PCIe`。
* **AI 与科学计算生态**：`PyTorch`（禁 `Pytorch`）、`TensorFlow`、`NumPy`、`SciPy`、`scikit-learn`（全小写连字符）、`pandas`、`vLLM`（首字母小写）、`llama.cpp`（全小写）、`DeepSpeed`、`FlashAttention`、`Hugging Face`（中间有空格）、`OpenAI`、`LaTeX`、`BibTeX`、`arXiv`（`X` 大写，首字母小写）。

### 1.4 行内代码反引号 `` `code` `` 边界纪律（拒绝“满屏麻子脸”）

AI 生成的 Markdown 文档常犯两个极端错误：要么代码标识符裸奔，要么把所有英文单词（连 `CPU`、`API`、`Python`）全都套上反引号，导致整段文字像长满麻子一样刺眼。

* **必须加反引号 `` `...` `` 的对象（字面代码实体）**：
  1. 函数名、方法名、类名、变量名：调用 `` `torch.compile()` ``、重写 `` `forward()` `` 方法、检查 `` `is_leaf` `` 属性。
  2. CLI 命令、标志位与快捷键：执行 `` `git rebase -i` ``、传入 `` `--max-num-seqs 256` ``。
  3. 文件名、目录路径与路由端点：修改 `` `/etc/sysctl.conf` ``、请求 `` `POST /v1/chat/completions` ``。
  4. 环境变量、配置项键名、数据字面量与状态码：设置 `` `CUDA_VISIBLE_DEVICES=0` ``、返回 `` `nullptr` `` 或 HTTP `` `502` ``。
* **严禁加反引号的对象（自然语言技术专有名词）**：
  * 编程语言名、框架名、硬件名、算法架构名、通用协议缩写：**裸写 + 盘古之白**。
  * ❌ 错误：我们使用 `` `Python` `` 和 `` `PyTorch` `` 在 `` `NVIDIA` `` `` `A100` `` `` `GPU` `` 上训练 `` `Transformer` `` 模型。
  * ✅ 正确：我们使用 Python 和 PyTorch 在 NVIDIA A100 GPU 上训练 Transformer 模型。

### 1.5 全半角标点与行内公式防污染规则

* **中文正文标点全角化**：中文句子内部一律使用全角标点（`，` `。` `；` `：` `？` `！` `、` `“”`）。严禁混入英文半角逗号 `,` 或半角实心句点 `.`。
* **并列顿号规则**：中文语境下三个及以上并列英文词之间用全角顿号 `、`（最后两项用`和/与`），不照搬英文牛津逗号 `, and`：
  * ❌ `支持 FP32, FP16, 和 BF16 精度。`
  * ✅ `支持 FP32、FP16 和 BF16 精度。`
* **LaTeX 公式混排**：
  * 公式内部严禁出现中文全角逗号或全角括号（❌ `$f(x，y)$` → ✅ `$f(x, y)$`）。
  * 行间独立公式（`$$...$$`）若是中文句子的有机组成部分，句末标点通常紧随公式逻辑或在正文收束，切忌在 `$$` 内部写中文全角句号 `。`。

### 1.6 代码注释、Git Commit 与图表图注（Caption）双语规范

1. **源码中文注释规范**：
   * 注释与 `//` 或 `#` 符号之间必须留 **1 个半角空格**（`// 释放页表锁`，禁 `//释放页表锁`）。
   * 注释内部的中英数字同样遵守盘古之白（`# 最多重试 3 次，超时上限 500 ms`）。
   * **只解释 Why（为什么这么绕 / 边界约束），不复读 What**：删掉 AI 最爱写的 `# 定义一个变量 i 并初始化为 0`、`// 返回结果` 这类废话注释。
2. **中英混排 Git Commit / PR 描述去 AI 味**：
   * 拒绝 AI 模板化的 `本次提交旨在优化……从而提升了……的体验`。
   * 标题行用干脆的**强动词 + 具体模块 + 修复现象**：`fix(kv-cache): 修复长序列抢占时的块引用计数泄漏`（不加句末句号）。
   * PR 正文直列 **`根因（Root Cause）` → `改动点（Changes）` → `验证指标（Benchmark/Test）`**，零寒暄。
3. **技术论文与报告图表图注（Figure / Table Caption）**：
   * 中文图注采用全角标点与盘古之白：`图 3：不同 Batch Size 下 P99 延迟与显存占用对比。`
   * 图内坐标轴若为英文（如 `Throughput (tokens/s)`），正文中引用时保持大小写与单位一致，切勿正文写`词每秒`而图上标 `tok/s` 却不加说明。

## 二、 术语一致性与反硬译法则（Terminology Consistency vs. Calques）

### 2.1 四象限术语裁决矩阵（何时留英？何时写中？）

| 象限 | 适用对象 | 处理准则 | 正反对比示例 |
|:---|:---|:---|:---|
| **象限 A：直接保留英文** | 尚无公认简短中译、或强行翻译会导致同行认不出的前沿词/缩写 | 直接写英文原词（遵循盘古之白），不必硬造生僻汉字词 | 保留 `Token`（除纯语言学论文外勿满篇写“词元”）、`KV Cache`、`LoRA`、`Agent`、`FlashAttention`、`Logits`、`Softmax`、`Pod`、`Hook`、`Webhook` |
| **象限 B：只写地道中文** | 计算机科学早有公认、零歧义、简洁中文译名的基础概念 | **一律写中文**，严禁中英散装夹杂（拒绝“假洋鬼子体”） | ❌ `这个 function 的 parameter 导致 memory leak，throw 了 exception`<br>✅ `函数传参不当引发内存泄漏，抛出了异常` |
| **象限 C：首现括注锚定** | 学位论文、学术期刊、正式白皮书中需严谨界定的核心术语 | **首次出现**写`标准中译（English Full/Abbr）`，后文固定只用其一 | 首现：`检索增强生成（Retrieval-Augmented Generation, RAG）`<br>后文：统一写 `RAG`（严禁一会写 RAG、一会写检索增强框架） |
| **象限 D：词形脱敏嵌入** | 英文术语嵌入中文句子作主宾定语时 | **剥除英语复数 `-s`、过去式 `-ed`、分词 `-ing` 尾巴**，用单数原形词根嵌入 | ❌ `消耗了大量 tokens` / `forked 出子进程` / `在 pre-training 时`<br>✅ `消耗了大量 Token` / `调用 fork 创建子进程` / `在预训练阶段` |

### 2.2 全文术语唯一性铁律（Zero Synonym Cycling）

AI 有严重的“同义词轮换强迫症（Synonym Cycling）”——为了显得词汇丰富，在同一页里把同一个东西换四种叫法。在技术写作中，**同义词轮换等于制造认知事故**：

* ❌ **AI 精神分裂写法**：首先构造**提示词**模板，随后将该 **Prompt** 输入大模型，通过调整**输入指令**中的示例顺序，观察模型对**引导语**的敏感度。
* ✅ **工程级唯一写法**：全文锁定一个词（要么全篇叫`提示词`，要么全篇叫 `Prompt`），从头到尾绝不变更。
* 常见必须二选一锁死的术语对：`微调` vs `精调`（推荐统一`微调`）、`词嵌入` vs `Embedding`、`推理` vs `推断`（大模型生成推荐统一`推理`）、`算子` vs `操作符`（深度学习底层推荐统一`算子`）、`检查点` vs `Checkpoint`、`吞吐量` vs `吞吐率`。

### 2.3 CS / AI 高危硬译（Calque）排雷大词典（32 个翻车重灾词）

大模型直译英文技术论文或文档时，极易把带有英语文化隐喻的行业黑话按字面硬翻（Calque），闹出外行笑话。遇到下表词汇，强制按地道 CS 中文改写：

| 英文原词 | ❌ 灾难机翻 / 生硬直译 | ✅ 地道 CS / AI 中文表达 | 核心语境说明 |
|:---|:---|:---|:---|
| **vanilla** (`vanilla Transformer`) | 香草 Transformer / 普通版 | **朴素 / 标准基础版** Transformer | 指不加任何花哨改进与 Trick 的原始基准结构 |
| **oracle** (`oracle policy/bound`) | 神谕 / 甲骨文策略 | **理想上界 / 先知基准（Oracle）** | 拥有完美未来或全局真值信息的理论上限对照物 |
| **ground truth** | 地面真相 / 地面实况 | **真实标签 / 标准真值（Ground Truth）** | 数据集中客观准确的标准答案（遥感领域除外） |
| **sanity check** | 理智检查 / 精神检查 | **合理性检验 / 冒烟自检（Sanity Check）** | 正式实验前用极简样本排查低级 Bug 的快速验证 |
| **non-trivial** | 非琐碎的 / 不平凡的（泛用时） | **绝非易事 / 颇具挑战 / 有实质难度** | 仅纯数学定理保留“非平凡解”；工程与算法分析中译为有难度 |
| **out-of-the-box** | 盒子之外的 | **开箱即用 / 原生内置** | 无需额外魔改配置即可直接运行 |
| **on-the-fly** | 在飞行中 / 飞翔地 | **运行时动态 / 实时在线**（如动态量化） | 边运行边计算生成，无需预先离线落盘 |
| **under the hood** | 在引擎盖下 | **底层实现 / 内部机制** | API 表面封装之下的真实系统运作逻辑 |
| **memory footprint** | 内存脚印 / 内存足迹 | **内存占用 / 显存开销** | 进程或模型在运行时占用的存储空间体量 |
| **in-the-wild** | 在野外 / 野生数据 | **真实开放场景 / 非受控自然场景** | 脱离实验室干净基准后的嘈杂真实世界环境 |
| **toy example / dataset** | 玩具例子 / 玩具数据集 | **极简算例 / 小规模验证集** | 用于快速讲清原理或验证可行性的微型构造样本 |
| **grounding** (`visual/factual grounding`) | 接地 / 落地 | **事实锚定 / 视觉定位（Grounding）** | 将模型生成内容绑定到外部可核查证据或图像区域 |
| **ablation study** | 消融研究 / 切除实验 | **消融实验** | 逐一拿掉模块以验证各组件真实贡献的标准实验 |
| **artifact** (visual / build) | 人工制品 | 图像领域：**伪影 / 瑕疵**；工程领域：**构建产物** | 切勿不分青红皂白统译为“人工制品” |
| **overhead** | 头顶开销 / 额外负担 | **额外开销 / 性能损耗**（通信开销、调度开销） | 为维持某种机制而付出的非核心计算/存储成本 |
| **trade-off** | 交易关闭 / 交换 | **权衡 / 取舍 / 折中** | 如延迟与吞吐量之间的权衡 |
| **tail latency** | 尾巴延迟 | **长尾延迟**（如 P99 / P999 延迟） | 慢请求分位点延迟 |
| **daemon** | 恶魔进程 / 精灵进程 | **守护进程** | 后台常驻服务进程 |
| **race condition** | 比赛条件 | **竞态条件 / 数据竞争** | 多线程并发未同步导致的时序依赖 Bug |
| **backpressure** | 背部压力 | **背压 / 反压机制** | 下游处理不过来时向上游发出的限流抑制信号 |
| **graceful shutdown** | 优雅的关闭 | **平滑停机 / 优雅退出** | 处理完在途请求、释放资源后再退出进程 |
| **off-the-shelf** | 货架下的 | **现成的 / 通用预训练的** | 直接拿开源或商业现成组件使用，未做专门定制 |
| **from scratch** | 从抓痕开始 | **从头训练 / 从零手写** | 不加载预训练权重或不依赖现成框架重头构建 |
| **boilerplate** | 锅炉板代码 | **样板代码 / 模板胶水代码** | 繁琐重复但不得不写的固定套路代码 |
| **heuristic** | 启发式的（生硬单用） | **启发式规则 / 经验法则** | 基于工程直觉与经验而非严格最优证明的策略 |
| **corner case / edge case** | 角落案例 | **极端边界情况 / 边角案例** | 罕见参数组合触发的异常分支 |
| **state-of-the-art (SOTA)** | 最艺术的状态 / 最先进的 | **当前最优（SOTA）** | 学术对比中直接写`刷新了当前最优（SOTA）结果`，少写机翻感极重的“最先进的” |
| **cherry-pick** | 摘樱桃 | **挑拣有利样本**（Git 操作中保留 `cherry-pick`） | 论文实验只挑好看的生成图展示 |
| **silver bullet** | 银色子弹 | **银弹 / 万能灵药** | 《人月神话》典故，常用于`没有银弹（没有一劳永逸的万能解法）` |
| **first-class citizen** | 一等公民（滥用时） | **原生一级对象**（如函数在 Python 中是一级对象） | 语言或系统原生直接支持传递、赋值与操作 |
| **tightly coupled** | 紧紧地被耦合的 | **紧耦合 / 强绑定** | 模块间依赖过深，牵一发而动全身 |
| **bottleneck** | 瓶子脖子 | **性能瓶颈 / 卡脖子环节** | 限制系统整体吞吐量的最慢一环 |

### 2.4 CS 四大核心子领域标准双语术语速查表

在撰写跨方向技术文章时，使用社区公认的标准译名（或公认保留词），避免生造外行词：

* **系统与网络（Systems & Networking）**：`Goodput`（有效吞吐量，区分于含重传开销的 `Throughput`）、`Jitter`（延迟抖动）、`Page Fault`（缺页中断）、`Context Switch`（上下文切换）、`Zero-Copy`（零拷贝）、`Lock-Free`（无锁）、`Idempotency`（幂等性）、`Split-Brain`（脑裂）、`Quorum`（法定多数派）、`Write Amplification`（写放大）。
* **大模型与机器学习（AI / LLM）**：`Prefill / Decode`（预填充阶段 / 解码阶段）、`TTFT`（首字延迟，Time to First Token）、`TPOT`（每输出 Token 延迟）、`Speculative Decoding`（投机解码 / 推测解码，全文锁死其一）、`Mixture-of-Experts, MoE`（混合专家模型）、`Attention Sink`（注意力汇聚点，勿译“注意力水槽”）、`Reward Hacking`（奖励作弊 / 钻奖励空子）、`Catastrophic Forgetting`（灾难性遗忘）、`Out-of-Distribution, OOD`（分布外）。
* **安全与密码学（Security）**：`Threat Model`（威胁模型）、`Trusted Computing Base, TCB`（可信计算基）、`Side-Channel Attack`（侧信道攻击）、`Prompt Injection`（提示词注入）、`Privilege Escalation`（权限提升 / 提权）、`Supply-Chain Attack`（供应链攻击）、`Zero-Day`（零日漏洞）。
* **前端、云原生与工程架构（Cloud & Web）**：`Hydration`（客户端水合/激活）、`Tree Shaking`（摇树优化 / 死代码消除，常直接保留 `Tree Shaking`）、`Serverless`（无服务器架构，常直接写 `Serverless`）、`Sidecar`（边车模式 / `Sidecar` 容器）、`Circuit Breaker`（熔断器）、`Rate Limiting`（限流）。

## 三、 根除“英文语法嵌套中文”（Avoiding English-Syntax-in-Chinese）

这是区分“机翻 AI 味技术文”与“母语级工程师好文章”的分水岭。以下十种句法手术专治披着汉字外衣的英语句子：

### 手术 1：切除英语形式主语外壳（`It is Adj. to...` / `There is...`）

* **病根**：照搬 `It is important to note that...`、`It is necessary to ensure...`、`There exists a problem where...`。
* **规则**：砍掉整层形式主语包装，直奔主干或改为祈使句。
  * ❌ **英式中文**：**它是至关重要的去确保**在调用销毁函数前所有子线程已被汇合，否则**存在着**内存损坏的风险。
  * ✅ **地道技术中文**：调用销毁函数前**务必先汇合（join）所有子线程**，否则可能损坏内存。

### 手术 2：拆毁“通过……的方式实现……”工具状语套娃（`By doing X, we achieve Y`）

* **病根**：英文学术与技术写作极爱用 `By introducing X, we achieve a significant reduction in Y`。AI 直译后满篇都是`通过引入……的方式，实现了对……的有效降低`。
* **规则**：让技术手段直接发出强动词，或拆成前后因果流水句。
  * ❌ **英式中文**：我们**通过采用**分块预填充（Chunked Prefill）**的方式，实现了对**首字延迟抖动的**有效平滑**。
  * ✅ **地道技术中文**：我们引入分块预填充（Chunked Prefill），压平了首字延迟（TTFT）抖动。

### 手术 3：纠正无生命主语强行拟人施事（Animacy Mismatch）

* **病根**：英语允许任何抽象名词做及物动词主语（`Recent years have witnessed...`、`This architecture enjoys low latency and suffers from high memory usage`、`This flag allows the compiler to unroll loops`）。生搬进中文会产生诡异的拟人翻译腔。
* **转换公式**：
  * `Recent years have witnessed X` → ❌ `近年来见证了 X 的爆发` → ✅ `近几年 X 发展极快`
  * `System X enjoys A but suffers from B` → ❌ `系统 X 享受着高吞吐但遭受着高延迟` → ✅ `系统 X 吞吐量虽高，但延迟偏大`
  * `Option X allows/enables users to do Y` → ❌ `该选项允许开发者去跳过校验` → ✅ `开启该选项即可跳过校验`（或`开发者可通过该选项跳过校验`）

### 手术 4：拆解右分支定语从句转换成的“的”字长龙

* **病根**：把英文名词后面的 `which / that / prepositional phrases` 全部往前翻成三四层`的`字定语压在名词头上。
* **规则**：单句中心词前严禁叠加超过 2 个长定语。将后置从句顺势拆为**紧随其后的动作分句**。
  * ❌ **英式中文**：调度器维护了一个**按照请求剩余显存预算和等待时长动态重排优先级的无锁双端**队列。
  * ✅ **地道技术中文**：调度器维护着一个无锁双端队列，按请求的剩余显存预算与等待时长动态调整优先级。

### 手术 5：清剿冠词寄生虫（满屏冗余的“一个 / 一种”）

* **病根**：英语可数名词单数语法强制带 `a / an`，AI 在翻译或生成中文时机械映射为`一个 / 一种`。
* **规则**：现代汉语没有冠词！除非是在强调精确数量 **`1`（而非 `2`）**，否则删掉 90% 的`一个 / 一种`。
  * ❌ **英式中文**：当**一个**客户端向**一个**未初始化的节点发送**一个**写请求时，会触发**一种**重试风暴机制。
  * ✅ **地道技术中文**：客户端向未初始化节点发送写请求时，会触发重试风暴。

### 手术 6：技术文档“被”字句三向分流（Microsoft / Google 本地化铁律）

* **规则**：拒绝照搬英文科技被动语态，按动作主体三向转化：
  1. **操作者是开发者/用户 → 转主动祈使句或“你”**：
     * ❌ `环境变量必须在启动脚本前被导出。` → ✅ `启动脚本前请先导出环境变量。`
  2. **执行者是系统组件 → 亮出组件主语或用汉语无“被”受事句**：
     * ❌ `脏页会在后台每隔 5 秒被刷盘线程写入磁盘，随后校验和会被更新。`
     * ✅ `刷盘线程每隔 5 秒在后台将脏页写入磁盘，并同步更新校验和。`
  3. **仅在异常中断、攻击或非预期破坏时保留“被”**：
     * ✅ `TCP 连接被对端强制重置（Connection reset by peer）。`

### 手术 7：破除“万物皆基于”与介词框架依赖（`based on / in terms of / for`）

* **病根**：AI 中文里几乎每三句话必有一个`基于`（`基于 Python 编写`、`基于梯度下降训练`、`基于实验结果可以看出`），加上`在……方面`（`in terms of`）、`对于……而言`（`for`）。
* **分流替换表**：
  * ❌ `基于 Rust 语言重构了解析器` → ✅ `用 Rust 重构了解析器`
  * ❌ `基于实验数据我们可以发现` → ✅ `从实验数据可以看出` / `实验数据表明`
  * ❌ `在吞吐量方面，新引擎更快` → ✅ `论吞吐量，新引擎更快` / `新引擎吞吐量更高`
  * ❌ `对于小批量请求而言，算子处于访存受限状态` → ✅ `处理小批量请求时，算子受限于显存带宽（Memory-bound）`

### 手术 8：恢复汉语“先时条、后动果”的自然时间轴语序

* **病根**：英语习惯先抛主句结果，再接 `if... when... because...` 状语从句；AI 生成中文时常出现半截倒装或条件后挂。
* **规则**：汉语严格遵守**“时间/场景 → 前置条件 → 执行动作 → 最终结果”**的单向顺流语序。
  * ❌ **英式语序**：函数会直接返回缓存句柄而不加锁，如果引用计数大于零的话，在高并发读场景下。
  * ✅ **地道汉语语序**：高并发读场景下，只要引用计数大于零，函数就免锁直接返回缓存句柄。

### 手术 9：剥除“们”字复数污染与连环代词“其 / 它”

* **病根**：把 `researchers / nodes / packets` 硬译为`研究人员们 / 节点们 / 数据包们`；把 `its / their / it` 硬译成满篇绕口令般的`其 / 它们`。
* **规则**：
  * 无生命名词严禁加`们`（绝无`服务器们`）；指人名词前已有数量词或表泛指时删掉`们`（`许多学者们` → `许多学者`；`开发者们需要注意` → `开发者需注意`）。
  * 同一句内最多出现 1 个`其`或`它`；指代距离超过一个逗号时，直接重复简短技术名词（如`该节点`、`锁`、`张量`）。

### 手术 10：报错信息与双重否定的正向直述

* **病根**：`Failed to bind port 8080` 译成`失败于绑定端口 8080`；`Do not disable TLS unless debugging locally` 译成绕口双重否定。
* **规则**：
  * 报错格式统一为 **`[动作 + 宾语] + 失败`**：`绑定 8080 端口失败`。
  * 双重否定改写为清晰的正向边界：`仅限本地调试时可关闭 TLS；生产环境请保持开启。`

### 场景 2：系统性能优化 / 排障复盘技术博客（Postmortem）

> **❌ Before（散装中英夹杂 + 被字句成灾 + 机械路标词）：**

> **✅ After（术语归位 + 意合因果流水句 + 强动词）：**

> **✅ After（严谨中文学术档——纠偏硬译 + 拆长句 + 规范公式留白）：**

### 场景 4：API / SDK 开发者文档说明

> **❌ Before（生硬机翻被动腔 + 指代模糊）：**
> `close(timeout)`：连接将通过调用此方法而被优雅地关闭。如果在一个指定的 `timeout`（以ms为单位）内未完成正在飞行中的请求们，它们将被强制取消并且一个 `TimeoutError` 将被抛出给调用它的线程。

> **✅ After（开发者中心主动语态 + 清晰条件时间轴）：**
> `` `close(timeout)` ``：平滑关闭当前连接，单位为毫秒（ms）。调用后系统不再接收新请求；若在途请求未在 `` `timeout` `` 时限内执行完毕，系统将强制取消剩余请求，并向调用线程抛出 `` `TimeoutError` ``。

### 场景 5：分布式系统架构设计文档（RFC / ADR 权衡记录）

> **❌ Before（端水句式 + 英文介词套娃 + 死物拟人）：**
> 在一致性与可用性方面，我们的架构面临着一个非琐碎的交易关闭。如果采用同步复制的方式，系统将遭受跨可用区RTT带来的高昂写延迟开销；而如果采用异步复制，虽然它享受到了极低的延迟，但是在主节点发生宕机的情况下存在着丢失最新提交的日志条目们的风险。

> **✅ After（工程直述 + 准确术语 + 明确权衡边界）：**
> 跨可用区（AZ）复制必须在一致性与写延迟之间做取舍：全同步复制每笔写入都要多等一次跨机房往返（约 `1.8 ms`），拉高写延迟；全异步复制虽然写延迟极低，但主节点一旦掉电，尚未同步的最新日志就会丢失。综合业务容忍度，账务核心表走多数派同步复制（Raft Quorum），普通审计日志走异步批量复制。

### 场景 6：安全漏洞通告（CVE Security Advisory）

> **❌ Before（欧化长定语 + 被动绕口令 + 拼写污染）：**
> 一个在 `jwt-auth` 中间件（版本低于v1.4.2）中存在的由未对头部算法字段进行严格白名单校验的原因所导致的身份验证绕过漏洞被安全研究人员们发现了。攻击者可以通过构造一个带有 `"alg": "none"` 的令牌的方式来实现对受保护API端点的未授权访问。建议所有用户们尽快进行升级。

> **✅ After（安全通告标准语序 + 去冠词去“们” + 祈使修复建议）：**
> `` `jwt-auth` `` 中间件（`v1.4.2` 之前版本）存在身份认证绕过漏洞：校验器未严格限制头部算法白名单，攻击者只需构造 `` `"alg": "none"` `` 的伪造令牌，即可免签名直接访问受保护的 API 端点。请尽快升级至 `v1.4.2` 及以上版本；暂无法升级时，可在网关层显式拦截含 `` `"alg": "none"` `` 的请求头。

## 五、 防矫枉过正护栏（Anti-Overcorrection Guardrails）

1. **严禁清洗代码块、命令行与报错原文**：Markdown 三反引号代码块（```` ``` ````）、终端真实输出日志、英文引用文献标题、API 原始 JSON 字段名必须 **100% 保持原样**，绝不能在代码字符串或注释里乱跑盘古之白替换或篡改术语。
2. **莫当“纯洁汉语原教旨主义者”**：不要为了“去英文”而把程序员耳熟能详的 `Bug`、`API`、`GPU`、`Token`、`Cache`、`Pod` 强行改成“程序臭虫、应用程序编程接口、图形处理器、词元、高速缓冲存储器、豆荚”。自然的技术母语就是该中文处纯正中文、该英文缩写处干脆保留英文。
3. **区分“合理工程术语”与“商业黑话”**：在分布式系统或软件架构文章中，`解耦（Decoupling）`、`幂等（Idempotency）`、`对齐（Memory/Preference Alignment）`、`链路追踪（Distributed Tracing）`、`底座（Infrastructure Base，慎用）` 若指代明确的技术实现，属于合法专业词汇，不要当作商业吹牛黑话误杀；只有当它们脱离具体技术指向、变成空洞修饰词（如`拉通端到端业务心智对齐`）时才予清除。
4. **保留必要的严谨限定**：技术规范中的 `当且仅当`、`线程安全`、`未定义行为（Undefined Behavior）`、`幂等性保证` 关乎工程契约正确性，改写句式时严禁丢失前置假设与并发边界条件。

## 六、 双语技术写作 10 项交付自检清单（Audit Checklist）

- [ ] **盘古之白准确无误**：汉字与英文/数字、数字与单位（`GB` / `ms` / `GHz`）之间均已留 1 个半角空格，且 `%`、`°`、全角标点两侧、斜杠 `/` 两侧**没有**多余空格。
- [ ] **专有名词大小写精准**：`GitHub`、`PyTorch`、`vLLM`、`macOS`、`LaTeX` 等无一拼写变形。
- [ ] **反引号边界清爽**：函数/参数/路径/配置键均已包裹 `` `...` ``，而语言名/框架名/硬件名均未滥加反引号。

## 七、 中英混排正则巡检与嵌入式 Prompt（Automated Lint & Prompt）

### 7.1 中英排版与翻译腔快速扫描正则（`ripgrep`）

在 Markdown 技术稿件上运行以下正则（注意排查时跳过代码块），可快速定位混排与硬译瑕疵：

```bash
# 1. 检测缺失“盘古之白”的中英/中数粘连
rg "([一-龥][A-Za-z0-9]|[A-Za-z0-9][一-龥])" doc.md

# 2. 检测多余空格（百分号前空格、全角标点两侧空格）
rg "([0-9]\s+%|[\s]+[，。；：？！、（）]|[，。；：？！、（）][\s]+[A-Za-z0-9一-龥])" doc.md

# 3. 检测高频技术品牌大小写拼写事故
rg "\b(Github|github|Pytorch|pytorch|Tensorflow|Javascript|MacOS|macos|Vllm|Latex|arxiv)\b" doc.md

# 4. 检测嵌入中文句子的英语词尾屈折残留（-s / -ed / -ing）与散装夹杂
rg "[一-龥]\s+[a-z]{3,}(ed|ing|s)\s+[一-龥]" doc.md

# 5. 检测高危 CS 硬译词与英式语法嵌套壳
rg "(香草|地面真相|理智检查|神谕|内存脚印|在飞行中|玩具数据集|它是(重要|必要|关键)的|通过.{1,20}的方式.{0,6}实现了|见证了|享受着|遭受着|[一-龥]{2}们)" doc.md
```
